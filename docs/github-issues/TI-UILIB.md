# TI-UILIB: UI Spec テンプレートに外部ライブラリ選定セクションがない

**ラベル:** `template`, `High`

---

## 背景

UI Spec はデザインシステム（Material Web）を参照してフロントエンドの実装仕様を定義します。Material Web はボタン・テキストフィールド・ダイアログなどの標準的な UI コンポーネントを提供しますが、グラフ・地図・リッチテキストエディタなどの専門的なコンポーネントは含まれていません。

## 問題

UI Spec テンプレートに、**デザインシステムが提供しない UI 要素に対する外部ライブラリの選定セクション**がありません。

この結果、専門的な UI 要素が必要なプロダクトにおいて、ライブラリ選定が行われないまま設計が完了してしまいます。ライブラリの選定漏れは、実装フェーズでの手戻りや、技術的な制約の見落としにつながります。

## PG1 での事例

- トレンドダッシュボードに折れ線グラフ＋カラーゾーン帯の表示が必要だったが、Chart.js の選定が行われないまま設計が完了した
- フィジカルスコア（0〜100）とメンタルスコア（1〜7）の Y 軸スケールが大きく異なることによるグラフ描画の問題が、ライブラリ選定時に検討されるべきだったが見落とされた

## 提案

UI Spec テンプレートに「外部ライブラリ依存」セクションを追加します。

```markdown
## 外部ライブラリ依存

デザインシステムが提供しない UI 要素に使用する外部ライブラリを定義する。

| 用途 | ライブラリ | 選定理由 | バンドルサイズ | 依存パッケージ |
|------|----------|---------|-------------|-------------|
| グラフ描画 | Chart.js | タップイベント対応、カラーゾーン帯描画可能 | ~65KB gzip | chartjs-plugin-annotation |
```

また、`product-model.json` の screens 定義を走査し、デザインシステム外の UI 要素（グラフ、マップ、エディタ等）が含まれる場合は、このセクションへの記入を必須とするガイドラインを `workflow.md` に追加します。
