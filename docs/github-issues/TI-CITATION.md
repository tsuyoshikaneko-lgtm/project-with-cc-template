# TI-CITATION: LLM が生成した文献引用の正確性を検証する仕組みがない

**ラベル:** `template`, `High`

---

## 背景

PRD の設計原則テーブルには「根拠」列があり、設計判断の学術的な裏付けを記載します。このテンプレートでは LLM（Claude）がドキュメントの生成を支援するため、文献引用も LLM によって記述されることがあります。

## 問題

LLM は文脈に適合するもっともらしい文献引用を生成しますが、その内容が必ずしも正確であるとは限りません。引用元の論文の主張を誇張したり、存在しない知見を捏造したり、効果量を別の指標に帰属させたりすることがあります。

現在のワークフローには、**LLM が生成した文献引用の正確性を原典と照合するステップ**がありません。この結果、不正確な根拠がそのまま設計判断に使われ、下流の Specs に波及します。

## PG1 での事例（8箇所）

PRD の文献根拠を査読した結果、以下のような不正確さが発見されました。

### 文献引用の不正確

| LLM が記述した内容 | 原典を確認した結果 |
|---|---|
| 「VAS よりも脱落率が低い」(Haslbeck 2025) | 原典ではコンプライアンスに有意差なしと報告されていた |
| 「EMA 疲労閾値は15項目、5分」 | 該当する出典が存在しなかった（LLM による捏造） |
| Hedges' g = -0.776 を「集中」への効果量として記述 | 原典（Lim & Dinges 2010）では「単純注意課題の失敗率」に対する効果量であり、「集中」への直接的な効果量ではなかった |
| 「主観ファースト原則」を実証済みの知見として記述 | 設計仮説であり、実証研究は確認できなかった |
| 「主要ウェアラブルは Z-score 正規化を使用」 | 個人ベースラインは使用するが、Z-score とは限らない（各社独自アルゴリズム） |

### 統計的数値の過大評価

- 「Pearson 相関の検出力 50-60%」→ 精密計算で 44.5%
- 「30日で十分」→ 自己相関を考慮すると power = 50-62%（一般的に不十分）

## 提案

### 1. PRD の根拠列に検証ステータスを追加する

```markdown
| 原則 | 根拠 | 検証ステータス |
|---|---|---|
| トレンド重視 | Baron et al. 2017 (Orthosomnia) | ✅ 原典照合済み |
| 最小入力 | Wrzus & Neubauer 2023 メタ分析 | ✅ 原典照合済み |
| 相関30日閾値 | 検出力計算 | ⚠️ 精密計算で power = 44.5%。PG1 では許容 |
| 主観ファースト | 臨床的助言からの設計仮説 | 📝 設計仮説（実証未確認） |
```

検証ステータスの定義:
- ✅ **原典照合済み**: 原典の主張と一致することを確認した
- ⚠️ **注記あり**: 一部不正確または条件付きで使用可能
- 📝 **設計仮説**: 実証研究に基づかない設計判断。仮説であることを明示する
- ❌ **不正確**: 原典と一致しない。修正または削除が必要

### 2. レビューゲートに文献照合を含める

「ワークフローにレビューゲートが組み込まれていない（TI-REVIEW）」の `review-prd` レビュー観点に「文献引用の原典照合」を追加します。LLM が生成した引用について、以下を確認します。

- 引用した論文が実在するか
- 原典の主張と記述内容が一致するか
- 効果量・サンプルサイズ等の数値が正確か
- 因果関係と相関関係が適切に区別されているか

## 関連 Issue

- 「PRD の設計原則が抽象的なまま下流に渡る（TI-ABSTRACT）」: 文献に基づく数値的主張の検証状態を管理する仕組みと連携する
- 「ワークフローにレビューゲートが組み込まれていない（TI-REVIEW）」: 文献照合をレビュープロセスに組み込む
